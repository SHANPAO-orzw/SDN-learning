知道 IP，怎样找到 MAC？

本课只看 IPv4、普通以太网、同一子网同一 VLAN；无代理 ARP 等特殊配置。目标是区分主机的 IP→MAC 映射与交换机的 MAC→接口映射，为以后解释地址欺骗建立基础。

ARP（地址解析协议）：在本地链路上解析 IPv4 地址对应的 MAC。本课目标主机与发送者处于同一子网，因此直接查询目标主机的 MAC。

设备IPv4MAC
A192.168.1.1002:00:00:00:00:0a
B192.168.1.1102:00:00:00:00:0b

已知两者同一子网，不靠地址看起来相似猜测。A 接交换机接口1，B接接口2，C接接口3，均允许转发。

从一次查询看过程

  1. A 要发送 IPv4 数据给 B，先检查本地 ARP 缓存。若没有可用的 B 的映射，就发出请求：“谁使用 192.168.1.11？请告诉 192.168.1.10。”请求包含 A 自己的 IP 与 MAC。
  2. 普通查询请求的以太网目的 MAC 是广播地址 ff:ff:ff:ff:ff:ff。交换机把它转发到同一 VLAN 中除入口之外允许转发的接口。此处是接口2、3。
  3. B 发现查询的是自己的 IP，通常单播回复 A：“192.168.1.11 对应 02:00:00:00:00:0b。”
  4. A 获得映射，缓存 192.168.1.11 → 02:00:00:00:00:0b，随后发往 B 的 IPv4 数据帧可使用 B 的 MAC。

原始依据：RFC 826，Packet Generation / Packet Reception。可选阅读这两段即可，不必现在背字段格式。

ARP 请求是本来就使用广播目的 MAC 的帧。上一课的未知单播泛洪中，目的 MAC 仍是某个主机的单播地址。两者都可能从多个接口发出，但不能混为一谈。

位置映射解决什么问题
A 的 ARP 缓存IP → MAC为本地下一跳选择以太网目的地址
二层交换机的 MAC 表MAC → 接口（及 VLAN）为帧选择出口

二层交换机转发请求时，也能按源 MAC 学到 A→接口1；转发 B 的回复时学到 B→接口2。ARP 的映射来自协议消息，交换机的学习来自帧的源 MAC 与入接口。

你的练习

A 已有 192.168.1.11 → 02:00:00:00:00:0b 这一有效 ARP 缓存，但交换机没有 B 的 MAC 表项。A 再向 B 发 IPv4 数据时：

  1. A 是否必须先重新发 ARP 查询？为什么？
  2. A 发出的数据帧，目的 MAC 是什么？交换机将如何转发？
