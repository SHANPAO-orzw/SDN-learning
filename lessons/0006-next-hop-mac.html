服务器在别的网络，查询谁的 MAC？

目标：区分最终目的 IP 与当前链路下一跳的目的 MAC。这能帮助你画出跨网络通信，也是以后解释转发规则的基础。

先根据路由决定下一跳，再用 ARP 解析本地下一跳的 MAC；跨网络时，下一跳通常是网关。

A ── 交换机 S ── 网关 R ── 其他网络 ── 服务器 C
角色IP本课 MAC
A192.168.1.1002:00:00:00:00:0a
R 面向 A 的接口192.168.1.102:00:00:00:00:01
C203.0.113.20不需要 A 获取

题设已知 A 与 R 的这个接口同子网，C 属于另一网络；A 到 C 的路由下一跳为 R。无 NAT、隧道或代理 ARP 等特殊机制。203.0.113.20 为文档示例地址，不要求实际访问。

只看 A 发出的第一段

  1. A 根据路由确定：给 C 的数据先交给 R。
  2. 若没有有效映射，A 用 ARP 查询 192.168.1.1 的 MAC，不是查询 C 的 MAC。
  3. 取得 R 的本地接口 MAC 后，A 封装数据帧，交由交换机转给 R。
A 发出的数据中值
IPv4 数据包的目的 IP203.0.113.20（最终服务器 C）
以太网帧的目的 MAC02:00:00:00:00:01（下一跳 R 的本地接口）

IP 数据包装在以太网帧中，它们可以分别指向最终目标和本地下一跳；交给 R 不等于把目的 IP 改成 R 的 IP。路由器之后还会决定后续下一跳，但本课先只分析 A 到 R。依据：RFC 826 的 Packet Generation，先由路由选择下一跳再进行地址解析。

普通 ARP 广播只在本地链路范围传播，路由器不会把 A 的这个广播原样转发到远端服务器所在网络。

你的练习

保持同一拓扑，A 改为访问另一远端服务器 D：198.51.100.8。到 D 的路由仍使用 R，且 A 没有 R 的有效 ARP 缓存。

请给出三项：ARP 查询的目标 IP；A 发出的数据包目的 IP；A 发出的数据帧目的 MAC。再用一句话说明为什么目的 IP 与目的 MAC 对应不同设备。

有不清楚的地方直接在聊天里问老师。可选原始阅读：上述 RFC 的 Packet Generation 开头，只抓 next hop，不必背英文。
