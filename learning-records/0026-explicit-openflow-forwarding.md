# 显式 OpenFlow 规则与往返通信

日期：2026-10-19。

## 实验配置

Mininet single,2；OVS secure 模式；OpenFlow13；无外部控制器；使用 --mac 和 --arp，提前设置静态邻居映射以排除 ARP 查询影响。

## 用户提供的实际证据

1. get-fail-mode 为 secure，dump-flows 为空；h1 ping h2 一次，100% 丢包。
2. 添加 priority=100,dl_dst=00:00:00:00:00:02,actions=output:2。ping 仍未收到回复；该规则 n_packets=1、n_bytes=98，说明至少一包命中规则，不把计数器当作接收主机抓包证据。
3. 添加 priority=100,dl_dst=00:00:00:00:00:01,actions=output:1。再次 ping 成功，0% 丢包；去 h2 规则计数从1增至2（196字节），去 h1 规则为1（98字节）。

## 结论与边界

在本拓扑与规则条件下，单向规则不足以完成 ping 往返；补齐返回规则后连通。用户独立解释：只有请求方向可转发，缺少s1发往h1的规则，所以h1收不到回复；往返规则理解检查通过。去向规则计数本身不单独证明h2收到请求。当前规则按目的 MAC 匹配，不限定源主机或ICMP，不能泛化成安全访问控制策略。未启用外部控制器，不称完成控制器实验。下一小主题可用更高优先级丢弃规则观察优先级与通信结果。
