# 高优先级丢弃覆盖转发规则

日期：2026-10-19。延续记录0026的secure/OpenFlow13双主机拓扑，无外部控制器，静态邻居已配置。

原有两条priority100规则分别把目的h2/h1帧转发到端口2/1，计数分别为2和1。

新增priority200、dl_dst=00:00:00:00:00:02、actions=drop。用户实测一次h1 ping h2，100%丢包；新drop规则n_packets=1、n_bytes=98，原去h2规则仍2包/196字节，返回h1规则仍1包/98字节。

证据支持本次数据命中高优先级丢弃规则，未执行低优先级转发规则。丢弃并不意味着匹配失败。规则按目的MAC匹配，影响范围不限ICMP，不将该配置称作攻击检测。

恢复对照已完成：用户执行--strict删除table0中priority200目的h2规则，随后ping成功（0%丢包）。dump-flows仅剩两条priority100规则；去h2计数2→3、196→294字节，返回h1计数1→2、98→196字节。允许→阻断→恢复的操作证据完整。

用户正确解释丢弃规则优先级更高、旧转发规则仍保留，删除丢弃规则后不必重装转发规则。但将执行丢弃的主体称为控制器；已反馈纠正：本实验无外部控制器，规则由命令行写入，交换机s1在数据平面匹配并执行丢弃。优先级及规则保留机制理解通过，控制/数据平面执行主体需后续间隔复核。
